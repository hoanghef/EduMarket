# 1. PROJECT PURPOSE

EduMarket is a B2C e-commerce website for selling:

- online courses
- downloadable learning materials
- digital educational content

The main goal is NOT to build a full LMS like Moodle or Udemy.

The main goal is to demonstrate a complete e-commerce system for digital goods.

The most important end-to-end business flow is:

Customer
→ browse courses
→ search/filter
→ view course
→ add to cart
→ apply coupon
→ checkout
→ COD simulation or VNPay Sandbox
→ successful payment
→ automatic course access grant
→ course appears in user library
→ user learns course content
→ protected file download through expiring link
→ course progress reaches 100%
→ completion certificate is generated

Admin must also be able to:

- manage courses
- manage categories
- manage users
- manage orders
- confirm COD payment
- moderate reviews
- manage coupons
- revoke course access
- restore course access
- view revenue reports

# 9. TOPIC 12 MANDATORY FEATURES

These are critical requirements.

## 9.1 Automatic digital delivery

When a payment is successfully verified:

```text
payment.status = SUCCESS
order.status = PAID
```

The backend must automatically grant access to every purchased course.

Flutter must NEVER decide whether payment was successful.

Only the backend may grant access.

---

## 9.2 Course entitlement

Use a dedicated entitlement system.

Example conceptual model:

```text
CourseEntitlement

id
userId
courseId
orderId
status
grantedAt
revokedAt
revokeReason
```

Status:

```text
ACTIVE
REVOKED
```

A user may only access protected course content when entitlement is ACTIVE.

---

## 9.3 Revoke and restore course access

Admin must be able to:

```text
ACTIVE → REVOKED
REVOKED → ACTIVE
```

When access is revoked:

- protected course APIs must immediately reject access
- protected files cannot be downloaded
- Flutter must show a clear revoked-access state

Authorization must always be checked server side.

---

## 9.4 Expiring download links

Private files must NEVER be directly exposed through public static URLs.

Correct flow:

```text
User requests download
→ backend checks authentication
→ backend checks ACTIVE entitlement
→ backend generates random token
→ token expires after a short period
→ temporary URL is returned
→ file is streamed by backend
```

Suggested expiry:

```text
10 minutes
```

Suggested default:

```text
maxDownloads = 1
```

Store only a token hash in the database.

Do not store plaintext download token.

---

## 9.5 Completion certificate

Track lesson completion.

When all required lessons are completed:

```text
progress = 100%
```

Backend generates one completion certificate.

Certificate should include:

- unique certificate code
- student name
- course title
- issue date
- verification URL

Certificate duplication must be prevented.

Provide a public certificate verification page/API.

# 10. PAYMENT FLOW

Support exactly these two payment methods:

```text
COD
VNPAY
```

## COD

COD is simulated because this project sells digital products.

Initial status:

```text
WAITING_CONFIRMATION
```

Admin manually confirms payment.

Then backend calls the same payment completion service used by VNPay.

Do not duplicate entitlement logic.

## VNPay

Use VNPay Sandbox only.

Required security:

- verify VNPay signature server side
- verify amount server side
- verify order
- make callback handling idempotent
- do not grant duplicate entitlements
- never store real card data

Payment success flow:

```text
VNPay callback
→ verify signature
→ verify amount
→ update payment
→ update order
→ grant entitlements
→ audit log
```

# 20. SECURITY REQUIREMENTS

Security is mandatory.

Implement:

## Authentication

- bcrypt password hashing
- no plaintext passwords
- HttpOnly authentication cookies
- Secure cookies in production
- SameSite configuration
- logout

## Login protection

- rate limiting
- maximum 5 consecutive failed login attempts
- temporary account lock
- reset failed attempt counter after successful login

## Authorization

Server-side role checks.

Middleware conceptually:

```text
requireAuth
requireAdmin
```

Never rely on hidden Flutter buttons for security.

## SQL Injection

Use Prisma or parameterized queries.

Do not create SQL strings using user input.

## XSS

Validate input and safely encode output.

Use CSP where appropriate.

## CSRF

Protect state-changing endpoints.

## IDOR

Always verify resource ownership.

Examples:

Customer A must never access:

- Customer B order
- Customer B certificate private data
- Customer B download token
- Customer B protected course content

## File upload security

Validate:

- extension
- MIME type
- size

Rename uploaded files.

Do not store private course files in a public executable/static directory.

## Rate limiting

Apply to:

- login
- sensitive actions

## Payment

Never store card details.

Use Sandbox only.

## Secrets

Use environment variables.

Never commit:

- database passwords
- JWT/session secrets
- VNPay secrets

Provide only:

```text
.env.example
```
